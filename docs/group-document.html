Problem, users and summary

The problem

Undergraduates track grades in scattered notes and spreadsheets and only discover late that a degree class has slipped out of reach. The arithmetic that matters is not the GPA already earned but the average still required over the credits left, and almost nobody works that out by hand. Repeat attempts, medical grades and non-GPA courses make the calculation easy to get wrong.

Intended users

Undergraduate students, first year through final year. The programme constants are set for the BICT degree at the University of Sri Jayewardenepura, and a single object at the top of the code changes them for any other 4.00-scale programme. Academic advisors can use the same page during consultations.

Summary

GradePath is a single-page web application that holds a student's transcript in their own browser. It shows the cumulative GPA, the degree class that GPA currently earns, the gap to the next class, and a trend of the cumulative GPA after each semester. The planner then answers the question the student actually has: given a target class and the credits still to take, what average is needed, which grade is that, and is the target still reachable at all. No account, no server, no data leaving the device.

The essential user journey

  1. Add a course: semester, code, credits and grade.
  2. The cumulative GPA, degree class and credit counts update immediately.
  3. Pick a target class and enter the credits still to be taken.
  4. Read the verdict: the average needed, the equivalent grade, and whether the target is secured, reachable, tight, or out of reach.

Technologies and tools

Built with

  • HTML, CSS and vanilla JavaScript. No framework, no build step, no dependencies at runtime.
  • CSS custom properties for the light and dark token sets.
  • Hand-written inline SVG for the chart.
  • localStorage for persistence.
  • Google Fonts: Newsreader, Public Sans, IBM Plex Mono, each with a local fallback stack.
  • Node.js for the test runners and the single-file build script.

AI and other tools

  • An AI coding agent in agent mode, running inside Visual Studio Code.
  • jsdom, to drive the real DOM in the journey tests.
  • Brave headless, to render and screenshot the page during review.
  • A hosted artifact page, to give the application a public URL.

Cases covered by those tests

  • Credit weighting: four credits at A with one at D gives 3.40, not the 2.50 a plain average would give.
  • An empty transcript reports no GPA rather than 0.00.
  • An E counts in the GPA and earns no credit; MC and W stay out of the GPA but keep their credits.
  • An excluded repeat attempt leaves every total.
  • Class boundaries at the exact values: 3.70 is First Class, 3.69 is Second Upper.
  • Semesters are listed in curriculum order however they were entered.
  • The planner refuses zero remaining credits and names an unreachable target instead of printing an impossible average.
  • The form rejects a missing grade, zero credits and an absurd credit value with a message that says how to fix it.
  • The transcript survives a reload, and clearing it empties every total.

Known limits

  • Data lives in one browser on one device. Clearing site data removes it. There is no account and no sync.
  • The grade points and class boundaries are the BICT ones. Another programme edits the constants at the top of assets/gpa.js.
  • The planner assumes the remaining credits all count towards the GPA.
  • Figures should be checked against the official academic record before any decision.
